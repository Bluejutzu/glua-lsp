A hook is a string and a function. Neither half is checked by Lua, so a typo in
the name produces a callback that simply never runs.

## Name completion and typo detection

`hook.Add` completes from 551 documented hooks, plus any custom hook your
workspace fires with `hook.Run` or `hook.Call`.

A name that is neither is reported, with the closest matches offered as quick
fixes:

```lua
hook.Add("PlayerSpawned", "x", function(ply) end)
--        ^ 'PlayerSpawned' is not a documented gamemode hook, and nothing
--          in this workspace fires it. Check for a typo.
--          Quick fix: change to "PlayerSpawn"
```

<Note>
  Custom hooks are fine. If anything in the workspace calls
  `hook.Run("MyAddon.Ready")`, then `hook.Add("MyAddon.Ready", ...)` is
  recognised. Engine events registered with `gameevent.Listen` count too.
</Note>

## Typed callback parameters

Callback parameters come from the hook's documented signature:

```lua
hook.Add("PlayerSay", "x", function(sender, text, teamChat)
  sender:Nick()    -- Player
  text:upper()     -- string
end)
```

This also applies to `function GM:PlayerSay(sender, text)` style definitions.

If a callback declares more parameters than the hook actually passes, that is
reported — the extra ones would always be `nil`:

```lua
hook.Add("Think", "x", function(ply)
--                              ^ 'Think' passes 0 arguments,
--                                but this callback declares 1
end)
```

## Hook tables

Entity, weapon, panel and tool files define hooks as methods on a table rather
than through `hook.Add`. Typing `function ENT:` completes that table and inserts
a full stub with the right parameters:

<CodeGroup>

```lua ENT
function ENT:Initialize()
  self:SetModel("models/props_c17/oildrum001.mdl")
  -- self is an Entity
end
```

```lua SWEP
function SWEP:PrimaryAttack()
  self:SetNextPrimaryFire(CurTime() + 0.5)
  -- self is a Weapon
end
```

```lua PANEL
function PANEL:Paint(w, h)
  surface.SetDrawColor(0, 0, 0, 200)
  -- self is a Panel
end
```

</CodeGroup>

| Table | Hooks from | `self` is |
| --- | --- | --- |
| `ENT` | ENTITY | `Entity` |
| `SWEP` | WEAPON | `Weapon` |
| `PANEL` | PANEL | `Panel` |
| `EFFECT` | EFFECT | `Entity` |
| `TOOL` | TOOL | `Tool` |
| `GM` / `GAMEMODE` | GM | the gamemode table |

<Warning>
  `hook.Add` only dispatches GM and SANDBOX hooks. `ENTITY`, `WEAPON` and the
  rest are metatable methods — `hook.Add("Initialize", ...)` will not do
  anything. Completion only offers hook.Add-able names inside `hook.Add`, which
  makes the distinction hard to get wrong by accident.
</Warning>

## Navigation

Go-to-definition on a hook name lists every `hook.Add` and `hook.Run` for it.
Rename updates all of them at once, which is how you rename a custom hook
without leaving a listener stranded.
